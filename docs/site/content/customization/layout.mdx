Compose editor parts inside your own grid or flex layout. `XlsxEditor.Root` creates no wrapper element. `XlsxEditor.Viewport` renders the element with the classes `xlsx-editor` and `xlsx-editor-viewport`. That element scopes the styles, names the landmark region, and holds the chrome parts and the grid.

## Arrange the editor

This grid puts an application panel beside the editor. The viewport needs a bounded height: here it fills the grid row, and `min-height: 0` lets it shrink.

<FrameworkTabs>
<Framework value="react">

```tsx
import { XlsxEditor } from '@xlsx-editor.dev/react';
import '@xlsx-editor.dev/core/styles/editor.css';

export function LedgerWorkspace({ bytes }: { bytes: Uint8Array }) {
  return (
    <div style={{ display: 'grid', gridTemplateColumns: '1fr 320px', height: 600 }}>
      <XlsxEditor.Root document={bytes}>
        <XlsxEditor.Viewport style={{ height: '100%', minHeight: 0 }}>
          <XlsxEditor.Toolbar />
          <XlsxEditor.FormulaBar />
          <XlsxEditor.StatusMessage />
          <XlsxEditor.Content />
          <div className="xlsx-footer">
            <XlsxEditor.SheetTabs />
            <XlsxEditor.ZoomControl />
          </div>
        </XlsxEditor.Viewport>
      </XlsxEditor.Root>
      <aside className="ledger-panel">{/* Application panel */}</aside>
    </div>
  );
}
```

</Framework>


</Framework>

Place each chrome part anywhere inside `XlsxEditor.Viewport`, in any order, or omit it.

| Part | Requirement |
| --- | --- |
| `XlsxEditor.Viewport` | Bounded height. Without a height in `style` or `className`, the grid has a height of 0. Its width never follows its content, so give it a width from its container, such as a grid column. It accepts `className`, `style`, and `label`. |
| `XlsxEditor.Content` | The grid. No application controls inside it. While no workbook is ready (none open, a load, or a failed open), the grid is hidden, so `StatusMessage` shows alone. |
| `XlsxEditor.StatusMessage` | Keep it in the layout. It is the only part that shows the reason for a refused edit. |
| `XlsxEditor.Toolbar`, `.FormulaBar`, `.SheetTabs`, `.ZoomControl` | Optional chrome parts. The toolbar takes parts, as [Toolbar](/docs/customization/toolbar) describes. |
| An element with the `xlsx-footer` class | The footer region that F6 visits. |

To read the editor state in your own panel, place the panel inside `XlsxEditor.Root` and call `useEditorState` or `useEditorCommand`. In Vue, a composable runs only in a descendant of `XlsxEditorRoot`.

## Fit a narrow panel

In a panel about 500 pixels wide, such as a panel beside a chat, the toolbar needs no setup. It moves the font family field into its **More** panel first, so size, bold, italic, underline, and font color stay in the bar, and then moves whole groups. On a phone-wide panel, leave out `ZoomControl`, so the sheet tabs keep the footer. To know when the panel is phone-wide, measure its width, for example with a `ResizeObserver`. The chat example in [`examples/chat`](https://github.com/eigenpal/xlsx-editor/tree/main/examples/chat) does this in `src/WorkbookPanel.tsx`.

```tsx
<XlsxEditor.Toolbar />
<div className="xlsx-footer" dir={useChromeDir()}>
  <XlsxEditor.SheetTabs />
  {phone ? null : <XlsxEditor.ZoomControl />}
</div>
```

## Show a sheet preview

To show a sheet outside the editor, such as on the card of a workbook in a chat, use the `SheetPreview` part inside `XlsxEditor.Root`. It paints the top-left window of the sheet as the grid paints it, with no headings and no selection. It paints again after each edit, after a sheet change, and when its size changes. Give it a size with `className`. It is a `span`, so a button or a link can hold it.

<FrameworkTabs>
<Framework value="react">

```tsx
<XlsxEditor.Root document={bytes}>
  <button className="card" onClick={openPanel}>
    <XlsxEditor.SheetPreview className="card-preview" />
    Sales.xlsx
  </button>
</XlsxEditor.Root>
```

</Framework>
<Framework value="vue">

```vue
<XlsxEditorRoot :document="bytes">
  <button class="card" @click="openPanel">
    <SheetPreview class-name="card-preview" />
    Sales.xlsx
  </button>
</XlsxEditorRoot>
```

</Framework>
</FrameworkTabs>

The `sheet` prop picks a sheet by its position in `snapshot().sheets`. Without it, the preview shows the sheet that the editor shows. The `zoom` prop sets the scale, from 0.1 to 4. The default is 0.6. The preview is hidden from assistive technology, because the control around it gives the name. To show the preview on its own, give it a `label`: it then has the `img` role and that name.

To paint into an element of your own without a framework, call `renderPreview(element, options)` on the editor instance. It returns `false` and changes nothing when no workbook is ready or the sheet is not a worksheet. It does not follow edits, so call it again after a `change` event. The editor paints it again by itself when fonts or pictures finish loading. The preview shows the values that the file stores and the edits wrote. It evaluates no formula.

## Control zoom

The `ZoomControl` part sets the zoom of the sheet. To set it from your own code, call `setZoom` on the editor instance. The zoom is a scale factor from 0.1 to 4, where 1 is 100%.

<FrameworkTabs>
<Framework value="react">

```tsx
<XlsxEditor.Root document={bytes} onReady={(editor) => editor.setZoom(1.25)}>
  {/* parts */}
</XlsxEditor.Root>
```

</Framework>
<Framework value="vue">

```vue
<XlsxEditorRoot :document="bytes" @ready="(editor) => editor.setZoom(1.25)">
  <!-- parts -->
</XlsxEditorRoot>
```

</Framework>
</FrameworkTabs>

Zoom changes only the view. It never changes the saved column widths, row heights, or the zoom that the workbook stores.

## Limits

- Keep the classes that `Viewport` supplies (`xlsx-editor` and `xlsx-editor-viewport`). The chrome styles and the keyboard find the editor through them.
- A chrome part outside `XlsxEditor.Viewport` has no styles. Place the chrome parts inside it. To theme a popup of your own outside the viewport, use `useScopeClassName`, as [Appearance](/docs/customization/appearance) describes.
- Changing `fonts` keeps the editor instance, the selection, and the undo history. A new `document` opens another workbook.
- For the props of each part, see [Layout and props](https://github.com/eigenpal/xlsx-editor/blob/main/packages/react/docs/layout-and-props.md).
