`@xlsx-editor.dev/i18n` holds the interface strings of the editor chrome. The English catalog is the source of truth. A locale catalog mirrors its shape, and a `null` entry falls back to English. To change the editor language, see [Language](/docs/customization/language).

## Install

The engine and each adapter install this package for you. Add a direct dependency only when you import a catalog, a type, or the translator from it:

```bash
npm install @xlsx-editor.dev/i18n
```

## Build a translator

`createT` builds a translator from a full catalog and a BCP 47 language tag, which the plural rules of the messages use. To translate with a partial catalog outside the editor, fill it with English first with `deepMerge`:

```ts
import {
  createT,
  deepMerge,
  en,
  type Translations,
} from '@xlsx-editor.dev/i18n';

const german: Translations = { _lang: 'de', zoom: { zoomIn: 'Vergrößern' } };
const t = createT(deepMerge(en, german) as typeof en, 'de');

t('zoom.zoomIn'); // "Vergrößern"
t('zoom.zoomOut'); // "Zoom out": the German catalog has no entry
// "Reset the zoom to 100%. The zoom is 150%."
t('zoom.resetAt', { level: '150%' });
```

`formatMessage` formats one message that is not in a catalog, with the same rules:

```ts
import { formatMessage } from '@xlsx-editor.dev/i18n';

formatMessage('{count, plural, one {# sheet} other {# sheets}}', { count: 2 }); // "2 sheets"
```

`@xlsx-editor.dev/i18n/en` is the English catalog as its own entry. For a translator inside the editor, use `useTranslation()`, as [Language](/docs/customization/language#translate-your-own-controls) shows.

## Exports

| Export | What it is |
| --- | --- |
| `en` | The English catalog |
| `locales` | Each catalog that the package ships, by its code |
| `LocaleCode` | The code of each catalog that the package ships |
| `Translations` | A partial catalog, the type of the `locale` prop. An alias of `PartialLocaleStrings` |
| `PartialLocaleStrings` | A partial catalog with its optional `_lang` tag and `_dir` direction |
| `DeepPartial` | Makes each nested key of a type optional |
| `LocaleStrings` | The shape of a full catalog |
| `TranslationKey` | Each key of the catalog in dot notation, such as `'zoom.zoomIn'` |
| `TFunction` | A translator: a key and the values of its placeholders give a string |
| `createT` | Builds a translator from a full catalog and a language tag |
| `deepMerge` | Fills a partial catalog with the entries of a full catalog |
| `formatMessage` | Fills the placeholders and the plural branches of one message, as `t()` does |
| `localeDirection` | The writing direction of a BCP 47 tag, `'ltr'` or `'rtl'` |
| `catalogDirection` | The writing direction of a catalog: its `_dir`, else the direction of its `_lang` |
| `chromeDirection` | The direction that a provider decides for the chrome, as the adapters decide it |

Each refusal message of the editor is one key that holds the whole message. The editor fills in its placeholders, and never joins keys or cuts translated text, so translate each message as one unit.

## Add a locale

To add a string or a locale to the package, follow [Contribute](https://github.com/eigenpal/xlsx-editor/blob/main/packages/i18n/README.md#contribute) in the package README. `bun run i18n:validate` fails when a locale file is out of step with `en.json`.
