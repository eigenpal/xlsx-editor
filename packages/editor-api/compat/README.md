# XlsxEditor and Office.js API compatibility

This directory measures the public surface of `@xlsx-editor.dev/editor-api` against a subset of the Office.js workbook object model in `@types/office-js`. The tooling is a port of PPTX Editor's `packages/editor-api/compat/` and `packages/editor-api/scripts/` at d4502552, which port DOCX Editor's at 5993bd223. Each script names its source path and commit in its first lines.

## The subset

`manifest.json` selects the members that the package implements:

| Class | Members |
| --- | --- |
| `RequestContext` | `workbook` |
| `OfficeExtension.ClientRequestContext` | `load`, `sync` |
| `OfficeExtension.ClientObject` | `context`, `isNullObject` |
| `Workbook` | `worksheets` |
| `WorksheetCollection` | `items`, `getItem`, `getItemOrNullObject`, `getActiveWorksheet` |
| `Worksheet` | `name` (read-only), `getRange` |
| `Range` | `address`, `values`, `numberFormat` (read-only) |

A row id leaves out the workbook namespace of Office.js, for example `Range#values`. Rows of the `OfficeExtension` namespace keep their prefix. `conformanceExceptions` names each selected member that the package declares differently, with its reason.

Each selected class leaves out the `ClientObject` plumbing that every upstream class declares again: `context`, `isNullObject`, `load`, `toJSON`, `track`, and `untrack`. `ClientObject` itself selects `context` and `isNullObject`.

Every Office.js member that is not in the table is outside the subset, and the package does not declare it, so TypeScript refuses a call to it. Inside the subset, a mode or an argument that the package does not support refuses with `NotSupported`, and a value of the wrong type refuses with `InvalidArgument`. A `load` option refuses at the call. Each other member refuses at the next sync, for example `getRange()` with no address, an address with a sheet name, or one value for a whole range.

## Layout

| Path | What it is | Who writes it |
| --- | --- | --- |
| `manifest.json` | The selected classes and members, and the conformance exceptions with their reasons. | Hand-edited. |
| `runtime-notes.json` | How each selected member behaves where the subset differs, as `equivalent` or `partial` with notes, as in PPTX Editor. `scripts/__tests__/conformance.test.ts` checks that each note names a selected member. | Hand-edited. |
| `provenance.json` | The pinned `@types/office-js` release: version, integrity hash, license, and source commit. | Hand-edited. |
| `definitely-typed-commits.json` | The reviewed DefinitelyTyped source commit of the adopted release. | Hand-edited. |
| `reference/workbook.inventory.json` | Normalized facts for every member of the selected classes in the pinned release. | Generated by `scripts/fetch-signature-inventory.mjs` (network). |
| `type-assert.ts` | `IsExact` and `Expect`, the strict type-equality helpers. | Hand-edited (copied from DOCX Editor). |
| `generated/conformance.generated.ts` | One compile assertion for each selected member, against the real public types of `src/index.ts`. | Generated by `scripts/generate-conformance.mjs` (offline). |
| `fixtures/source-compat/*.ts` | Office.js workbook code written against the `XlsxEditor` namespace. The compiler checks it; nothing runs it. | Hand-edited. |
| `tsconfig.json` | The project that compiles `type-assert.ts`, `generated/`, and `fixtures/` against the package sources. | Hand-edited. |

The inventory keeps only the selected classes, with every member of each, because the workbook namespace is far larger than the conformance check needs. It also leaves out the requirement set of each row, because the requirement set names carry the namespace name, which the repository does not write.

## Conformance assertions

From the repository root, run:

```bash
bun run --filter '@xlsx-editor.dev/editor-api' compat:generate
```

The command writes `generated/conformance.generated.ts` from `manifest.json` and `reference/workbook.inventory.json`. Each selected member gets one assertion:

- A method compares all its overloads, in reference order, with the real member, for example `XlsxEditor.Worksheet['getRange']`.
- A property compares its read type, `readonly`, and `?` with `Pick` of the real class, for example `Pick<XlsxEditor.Range, 'values'>`.
- A writable property also gets a write check: the reference write type must assign to the real setter.

`IsExact` checks both directions, so a narrower or a wider type fails. A reference type names the package export of the same name, so a missing export fails as a compiler error. `scripts/__tests__/conformance.test.ts` compiles the project offline in `bun run test`, checks that the generated file is current, and proves that a drifted reference or a drifted declaration fails.

## Adopting a new upstream release

1. Add the reviewed DefinitelyTyped commit of the release to `definitely-typed-commits.json`.
2. Update `provenance.json` with the version, the integrity hash, the tarball URL, and the commit.
3. Run `bun run --filter '@xlsx-editor.dev/editor-api' compat:fetch-inventory`. It downloads the pinned release and checks its integrity hash.
4. Run `compat:generate` and `bun test packages/editor-api`, and review the diff.

Tests and builds never fetch the network.
